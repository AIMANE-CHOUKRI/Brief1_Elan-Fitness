Today, we learned about the Agile methodology, what it contains/ what it deems important, and how it is implemented into a workflow. And the main issue that Agility tackles is the demands and request of the client, because unlike how old workflows used to be (ex: Cascade method) where the client's request is made at the start, and then the project gets worked on until it gets finished, then it is shown to the client for review. It can lead to alot of problems later on, such as there being something that the client doesn't like/want, then everything might need to be redone from beginning to end, which can get expensive ,time consuming, maybe even demoralizing for some people. And Agility came to put an end to that problem, because of it's heavy emphasis on bringing about the client's wants and needs, How? because in the Agile method, the client is an active participant during development, whether it be during the conception phase, or the development phase, the client gets a say in everything, and so it is pretty much impossible for a project to have to get redone from scratch for whatever reason, which can save a lot of money for the project leader, and negate having to change deadlines (or having to pay for breaching a deadline). 

With the 3 main parties of an Agile (Scrum) workflow being: 

&#x09;-- Product Owner : Stays in communication with the client (Voice of the Client) ; 

&#x09;-- Scrum Master : main orientator/coach of a project that uses Agile/Scrum methods 	   to help the devs in achieving and efficient workflow ;

&#x09;-- Dev Team : Who work the code and the technicalities.

Today, we learned about the importance of effort in making a website more accessible to a wider audience, with 1 of the 2 ways being that your website has a high correlation with a user's input (with the example of adding tags to a post in Instagram and how that helps people in finding the content they are searching), and the same can be done with how a robot ranks a particular website to determine it's priority after a user searches it (whether it appears first or second, etc...) whether it be by efficiently using the site's title or "meta" description to your advantage. And another way is to simply use money, and give it to your web browser's advertising services so that your website appears more often than normal. As well as looking for ways to increase your website's presence and impact on the user, such as having high resolution pictures/videos (iow: they aren't blurry or hard to figure out), and having an interface that doesn't require an explanation on how to navigate it, or using consistent colors that pair well with each-other. All of these concepts can have an impact on a user's first time entering your website, and the first time can always be the last time. So it is quite imperative that a web developer should look to make their websites as presentable as possible in order to capture a larger audience. However, going all-out on the design of a website does have it's cons, such as the speed of the website (or how long the page takes to load, or how long it takes for a button to do it's role), which can definitely impact the mood of the user, especially if they're in a hurry. And so ideally, there should be a balance between the outer looks of a page and it's inner works, although and imbalance can be used advantageously, such as putting a bit more importance on the design of a particular page, which can impact the speed a little bit depending on how much you want the page to look good aesthetically. Or you can do the opposite, and make a web-browser game that has really smooth and interactive gameplay, but the game is a rough 2D instead of 3D (Terraria as an example). Which has proven to be equally or even more fun than a AAA Video Game (High-end graphics and all that), mainly thanks to how smoothly the game runs consistently.
